这是我的第一个项目，也是这个博客的第一篇技术记录。写下来有两个原因：怕自己忘了当时为什么这么定，以及这些取舍本身挺有意思。

## 先量尺寸，再谈设计

动手之前我把所有图过了一遍，这一步救了我：

| 文件 | 尺寸 | 比例 |
| --- | --- | --- |
| `B.jpg` | 2560 × 1280 | 2:1 横幅 |
| `B1–B4.jpg` | 1280 × 2560 | 1:2 竖幅 |
| `A1–A3.jpg` | 896 × 1792 | 1:2 竖幅 |
| `C1–C3.jpg` | 557 × 941 | 约 0.59 |
| `D1–D3.jpg` | 986 × 1648 | 约 0.60 |
| `Droplet.png` | 640 × 1142 | 约 0.56 |

我原本以为 `B1` 到 `B4` 是把 `B.jpg` 横着切成四段。量完才发现不是，它们是竖着切的四条，每条 1:2。四条竖图并排站好，正好又拼回 2:1 的全景。

首屏长什么样，就是这句话决定的。

后面几组素材（`A1–A3`、`C1–C3`、`D1–D3`）是同一种切法：一组三张，并排才是一幅完整的画。这个事实决定了日志区只能按三列排——见下面「一页一张图」那一节。

## 舷窗不是四个矩形

第一版我做了四块并排的圆角矩形：内描边、inset 阴影压暗四周、再叠一道 105° 的斜向高光当玻璃反光。做出来不难看，但它不是舷窗，是四块手机屏。看一眼就知道哪里不对——窗和窗之间只有一道 16px 的缝，轻飘飘的，那堵墙没有厚度。

重做的时候把它拆成四层：

1. **舱体**，静止不动。金属拉丝、接缝线、四边压暗。
2. **三道隔柱**。不是缝，是柱子：金属渐变、结构肋、上下各一颗螺栓，柱身上还有一盏红灯在慢慢呼吸。
3. **玻璃**。一层很淡的反光，跟着鼠标同向移动，因为它映的是舱里。
4. **景观**，也就是 B1 到 B4，放大到 1.18 倍。

真正起作用的是第四层的位移量：鼠标动的时候，窗外的景比窗框动得多。四扇窗的深度系数分别是 1.0、0.78、0.56、0.38，越靠边越小，假装这是个弧形的舱盖。人会本能地读懂这种错位，这是整个首屏唯一的"3D"。

旧版那条规矩没变：`object-fit: cover` 在这里裁的是上下，不是左右。横向不裁，四扇窗之间的画面才是连续的，中间的隔柱才真的像把一整幅风景切开了。

窄屏怎么办：四扇竖窗在 375px 上会瘦成四条门缝，所以窄屏直接换成 `B.jpg` 单幅全景，反正它本来就是拼好的那一张。

## 删掉首屏那段话

首屏原来不止铭牌。眉题下面还有一行导语（"在真空里，一滴水保持最完美的形状……"）和一个 `Tracking…` 光标。

那行字单独看没问题，放到画面上就成了麻烦：首屏被切成上中下三块，水滴被夹在中间那块里，左右两边各留一条谁也说不出该放什么的空白。而且它和左上角的 HUD 在说同一件事，说的是重复的。

删掉之后首屏只剩三样东西：顶端铭牌、正中水滴、底端 `SCROLL`。信息少了一半，视线反而顺了——这也是我这一版学到最多的一条：**首屏里，能删的都该删掉**。

顺手把站名也改了形。原来那句话占着位置的时候，"圣母的眼泪"是整屏最大的白色字；导语一删，它就没有对手了，再摆那么大就是喧宾夺主。现在它是一块小铭牌，跟水滴的跟踪环错开，不抢中心。

## 水滴为什么会"看着你"

参考的是 oil.oil 网站上那只跟着鼠标转头的小狗。那个效果的本质是帧序列 scrub：预先生成一串姿态，鼠标位置映射到第几帧。

那需要 AI 生成一段视频，要配 API Key、要 FFmpeg、要几 MB 的资源。对一颗近乎轴对称的镀铬水滴，我判断不值当，先用纯前端模拟，成本是零：

```js
// 弹簧跟随：目标位置 = 指针方向 × 最大位移
vel.x += ((target.x - pos.x) * K - vel.x * D) * dt
pos.x += vel.x * dt
```

所谓"朝向你"，是四件事叠出来的错觉：

1. **位移**，朝指针方向偏，最多 26px。幅度必须小，再大就成了跟着鼠标跑的贴纸。
2. **倾斜**，按水平偏移量转一点点，最多 10°。
3. **挤压拉伸**，按速度做 squash & stretch，动得快就拉长一点，像表面张力被拖曳。
4. **拖尾**，六个缩小副本，越小越淡。

拖尾是这里面最见功力的一环。我采样的是过去的位置，不是当前位置，并且让它们反向偏移一点，这样水滴加速时尾巴是真的被甩在身后，而不是黏在身上。

位置后来挪到了页面正中。原来它在右上角，理由是"点缀不该占 C 位"；但四扇舷窗的中心本来就是画面重心，光从那儿穿过去，水滴放在那儿才像是真的悬在窗外。挪过去之后它反而更安静了——因为它终于待在该待的地方。

## 星空不该跟着鼠标动

第一版的星空跟着指针做视差：鼠标往右，整片天往左滑一点。

技术上没毛病，用起来别扭。读的时候手会无意识地动，整片背景就跟着一起晃——那不是"有深度"，那是晕。而且它和舷窗那套视差在打架：舷窗的错位有物理理由（窗框近、景色远），在零重力的深空里没理由让星星跟着一个字都没点的光标跑。

现在它只做两件事：

1. **常态漂移**，每秒 5.5px 乘上每颗星的深度系数，近的走得快、远的几乎不动。船在走，星在退。滚动再额外叠一点纵深。
2. **偶尔一颗流星**，间隔 5 到 13 秒随机，一条带亮头的短划线，头尾各淡一次。最多同时两颗。

鼠标不再驱动星空里的任何东西。少了一个交互，多了一片安静。

## 它消失过一次

首屏右上角那颗水滴，曾经整整一天不显示，只剩一个跟踪环挂在原地。

第一轮我以为是不支持某个 CSS 属性，全站改了写法，没用。第二轮我让无头浏览器把它的包围盒打出来，看到的是 `1 × 230`。图片加载正常，位置正常，透明度正常，宽只有一像素。

原因是我自己写在 reset 里的那行：

```css
img { max-width: 100%; display: block; }
```

水滴的装配体是个 0×0 的定位锚点（所有子元素都靠绝对定位挂在这一点上）。`max-width: 100%` 在这个容器里算出来是 0，图片就被钳到了 1px 宽。加上一句 `max-width: none`，立刻好了。

从看到到修好四十分钟。教训很具体：**在 0×0 锚点容器里放图片，必须显式解除 max-width。**

还有一处同类问题：跟踪环的读数标签原本挂在环的右下角，位置用百分比算，直接溢出到了视口外面。改成挂左下角、用 `translateX(-100%)` 收边。

## 第一版被推翻了

第一版做完后，反馈很直接：风格偏老。

我一开始以为调调参数能救。后来发现救不了，因为老的不是配色，是形制。衬线大标题、毛玻璃、圆角药丸按钮、镀铬渐变——这套语汇属于 2020 年前后的科幻落地页，你把颜色全换掉，它还是那一套。

于是全量重做。近纯黑底、等宽字体、1px 细线、方角和切角、红色只用在警示上。舷窗换成上面那四层。水滴外面套上跟踪环和 `PROBE-001` 的读数。区块标题变成 `01 舱段档案 // 关于` 这种编号格式。左上角有个距离读数在每秒递减，因为它在逼近。

骨架倒是没动：水滴的弹簧物理、md 内容管线、哈希路由都留着，重做的是视觉层。

顺带删掉三样东西：横向无缝滚动的词条带、顶部滚动进度条（同一个理由，观感廉价）、以及那个粉紫渐变的药丸按钮（参考文档里的配色属于它自己那套紫色主题，搬进深空配色只能继承形制，颜色得重做）。

参考文档给的是形制，不是教条。这句话我写进设计规范了，免得以后又照搬回来。

## 一页一张图，三列拼成一幅

日志区最初是两列卡片。问题是那几组素材是三张一组的，两列排下去，`A3` 和 `C1` 会被硬塞进同一行——原本拼在一起的一幅画，被拦腰截断。

改成三列之后，规则变得很简单：**一篇内容页只放一张图**，同一行的三张按 `order` 顺序排好，自然拼回一整幅。`A1–A3` 是第一行，`C1–C3` 是第二行，后面的组依次往下。

为了让拼接成立，这一行的卡片做了三件自己才发现的小事：

- 去掉边框和列间距，否则画面之间会出现一道道缝；
- 封面只显示整图的下 3/4，上面那段留白反正也是空的；
- 卡片文字区的边框改成"左、下，加每行第三张的右"，拼出来的是一整块表格，而不是九个各自为政的方块。

悬停时整格从整幅画里浮起来（`translateY(-6px) scale(1.035)`，封面再补一点 `scale`），移开归位。拼接卡也参与——这一条是刻意的，不然一行里只有一半的格子会响应鼠标。

## 极昼模式：给长文一个亮场

深底浅字好看，但看长文看久了眼睛会累。所以在文章页加了一个开关，叫**极昼**。

打开之后，正文翻成浅灰蓝的纸面配深色字（`#172635`），对比度拉到顶，代码块、行内代码、封面都换成亮场配色，浏览器地址栏也换成浅色。星空整个熄灭——因为极昼照的是舱内，窗外该黑还是黑的，首屏维持黑暗森林不变。这是刻意的：可读性和氛围不该二选一，而是各管各的地盘。

极昼的背景上跑着三体运动。第一版我图省事，画了三个静态的圆，被一眼看穿是敷衍。现在的版本算的是真的：

- 初始条件用 Chenciner–Montgomery 的 8 字形解——三颗等质量恒星在一条 8 字轨道上循环，谁也不落下；
- 用 leapfrog 积分逐帧推，加了一点点软化避免数值爆掉；
- 三颗太阳颜色不同，各自拖一条逐渐淡出的尾迹，把那条公共引力轨道画出来。

它只在极昼时出现，也只出现在文章页。首页不需要它。

## 两个不妥协

**可读性。** 深底博客最容易死在对比度上。正文 `#e9eef7`，接近白而不是灰；行宽锁 68ch，行高 1.85。文章页关掉一切大型动效，右下角那颗徽章只有 72px，它的作用只是提醒你这艘船还在。

**降级。** `prefers-reduced-motion: reduce` 时，水滴不注册任何监听，只画一帧静态，所有过渡归零。这不是加分项，是及格线。有人看不了动效，站也得能用。

## 技术选型

Vite 加原生 JS，没有框架。文章是 `content/posts/*.md`，构建时内联成字符串，运行时用 markdown-it 渲染。哈希路由（`#/post/xxx`），这样 GitHub Pages 不需要任何服务端配置。零外部字体，首屏只有那几张图。
